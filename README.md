# 高校课程标准映射与课程改革审阅平台

面向教研人员、课程负责人和院系审阅人的课程图谱平台，支持培养目标、毕业要求、课程单元、教学活动、考核任务映射，以及有向图检查、覆盖矩阵、拖拽连边、自动保存、批量审核和课程地图导出。

## 技术栈

SvelteKit + Skeleton UI + Svelte stores + SvelteKit Form Actions + TanStack Query + Zod + Vite + TypeScript

## 本地运行

```bash
npm install
npm run dev
```

访问 `http://localhost:62049`，生产构建使用 `npm run build`。

## 核心工作流

- 在培养目标、毕业要求、课程、单元和考核之间建立有向映射。
- 自动检查前置关系、覆盖缺口、重复映射和不完整考核证据。
- 课程负责人提交修订，院系审阅人逐条退回、附议或要求补充证据。
- 比较版本覆盖变化，恢复草稿并导出专业课程地图。

## 可恢复修订流程（并发编辑）

课程负责人与院系审阅人可能同时编辑同一门课，系统以修订日志替代“后保存覆盖”：

- **所见版本（乐观并发）**：每次提交（课程节点、映射、审阅提交、审阅意见）都携带 `baseRev`。所见版本即当前 head 时快进；落后时触发三路合并。
- **未冲突直接合用**：双方改动落在不同项时自动合并，互不覆盖。
- **同项双改保留两份**：同一项双方都改过（如双方都改 C-308、都给同一审阅项下结论），工作版本保持当前值，后提交值作为 `incoming` 并列保存并标明提交人/角色/来源修订，在“修订中心”裁决采用哪一份。
- **发布锁版**：发布生成独立的 release 快照，仅纳入已采用（已附议）的修改；退回与待审阅项仍留在工作队列，可补充证据后重新提交；锁版后的新修改保存为新版本，不影响已发布快照。
- **旧版可查**：全部修订与锁版快照保存在日志中，可随时按修订号只读查看。
- **写入失败可恢复**：写盘采用 WAL（先落待写日志、再提交主写入）。主写入失败时改动留在待恢复队列并记录失败时修订号，重新打开页面或手动点击恢复时按修订号重放；`changeId` 幂等保证同一条改动绝不重复生成记录。
- **旧数据兼容升级**：缺少修订号的旧数据（含 v1 localStorage）首次加载时整体升级为第 1 版，之后的修改按新版本保存。

核心为纯函数引擎 `src/lib/revision.ts`，语义自检：

```bash
npm run verify:revisions
```
